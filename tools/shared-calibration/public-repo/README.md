# MentorRecorder 共享校准

本仓库存放「导随记录器」（MentorRecorder）玩家分享的**共享校准码**。

游戏每次更新都可能重排报文编号（opcode）。同一区服、同一客户端版本的编号编译在客户端内，对所有玩家一致。
因此一名玩家在软件中校准成功后，可以将结果分享出来，其他玩家的软件无需逐一重新校准。

## 软件如何使用本仓库

- **只读下载。** 游戏更新后本机没有可用档案时，软件读取 `index.json`，再按提交号下载同一区服、同一客户端版本的校准码文件。
  在用的档案来自共享校准而尚未完整核实，或者按排本推断匹配时，软件按同样的节流（6 小时内至多一次）重新读取索引，以便得知撤销或更准的校准码。
  软件不向这里上传任何东西。
- **先核实，再使用。** 下载的校准码不是档案。软件先在玩家本机流量中按结构核实：至少要等登录时的换区报文核实通过，才生成档案并开始记录；
  开始记录后，排本与进本报文仍会继续核实。核实不通过时继续本机校准，已有的校准证据不会丢失。
  一份错误的校准码在被识别出来之前，可能使记录缺失或有误；软件判出它与本机流量矛盾后会停用它，并把它生成的记录标记为待复核。
- **可以关闭。** 获取共享校准是软件默认开启的两类出站请求之一；另一类是检查新版本，读取主项目发布页上的版本号文件，与本仓库无关。
  两者都可以在设置中关闭。此外还有玩家自行开启的在线语音，默认关闭，同样与本仓库无关。
  请求的发出时机、携带内容与关闭方式，均写在软件的隐私边界说明中。

## 校准码包含与不包含的内容

一份校准码是 `MRC1.` 加上一段压缩后的规范化 JSON。

| 有 | 没有 |
|---|---|
| 格式版本、区服（`CN` / `GLOBAL`）、客户端版本号 | 角色名、服务器、账号、IP 地址 |
| 依据的随包模板编号与模板哈希 | 时间戳、样本数、排过哪些随机任务 |
| 匹配方式，以及这种方式需要的报文长度、字节偏移或状态值 | 说明文字、文件路径、任何报文正文 |
| 学到的几个报文编号（匹配弹窗、换区、副本、职业） | |

校准码的编号 `code_sha256` 是规范化内容的 SHA-256，仓库中的文件名取其前 12 位。

## 提交方式

在软件中校准成功并核对校准时间线之后，点击「分享给其他玩家」，该按钮需要由相应的软件版本提供。浏览器会打开本仓库预填好的 Issue 页面，
勾选确认后提交。GitHub Action 会自动校验并发布，在 Issue 下回复结果并关闭 Issue。正常情况下无需维护者参与。

没有 GitHub 账号的玩家可以将软件复制出的校准码交由他人代为提交，下述规则按代交者的账号计算。

## 受理规则

- 提交的 GitHub 账号**注册满 30 天**。
- 校准码里的客户端版本号必须是游戏客户端的版本号格式，形如 `2026.09.01.0000.0000`，
  其中的日期不得晚于提交日（按 UTC 计算）的次日。
- **每个 GitHub 账号，每个区服与客户端版本，同时只有一份在用的校准码。** 该规则按账号的数字编号计算，改名不能增加份数。
  再次提交同一份不重复计数；提交另一份则**替换**先前那一份，见下一节。
- **每个账号的提交次数有上限**：同一区服与客户端版本最多先后提交 3 份不同的校准码；每天最多为 2 个区服与客户端版本提交，
  日期按 UTC 计算（北京时间每天 8:00 起算新的一天）。每一份开启了共享校准的软件都会下载索引，而索引大小有上限，这两条限制使单个账号无法把它写满。
- 账号提交的校准码被维护者撤回之后，该账号在这个区服与客户端版本下的提交**暂停受理**，直到维护者复核，见「撤销」一节。
- **不设名额上限。** 不同账号提交完全相同的校准码时合并为一条，`submitters` 记为提交过它的不同账号数。
  软件优先核实提交人数多、发布早的校准码，每个版本最多同时核实 8 份。
- 校准码必须能用 `templates/` 中的随包模板按结构重建。格式错误、模板不匹配或结构不合法的提交一律拒绝，并在 Issue 中说明原因。
- 被拒绝的 Issue 将被关闭。修正后应提交新的 Issue，编辑已关闭的 Issue 不会被重新处理。

## 更正自己提交过的校准码

发现自己提交的那一份有误，或后来校准出了更好的一份时，**不需要联系维护者**：在软件里重新点一次「分享给其他玩家」，
照常提交新的 Issue 即可。Action 会用新的一份替换你先前为该区服与版本提交的那一份，并在回复中说明：

- 先前那一份只有你一个提交者时，它会被撤回（`revoked: true`，条目保留），其他玩家的软件不再使用它。
- 先前那一份还有别的账号也提交过时，它继续保留，只是不再计入你的提交，`submitters` 相应减一。
- 已被撤回的校准码不会再次发布，因此不能把它重新提交回来；请提交一份新的。
- 这样替换下来的校准码不影响你继续提交。但如果你的校准码是被**维护者**撤回的，这个账号在该区服与版本下的提交会暂停受理，
  直到维护者复核后解除；如认为撤回有误，请在 Action 拒绝受理的那个 Issue 下留言说明情况。

## 报告校准有误

用到的校准码有问题（弹窗时误报匹配、记录不到、职业或副本不对等）时，用
[「报告校准有误」](../../issues/new?template=report-calibration.yml) 表单告诉维护者：填区服、客户端版本与现象即可，
不必附上校准码。

自动流程只做三件事：校验栏目、打上 `calibration-report` 与 `needs-maintainer` 标签、回复一次「已收到」。
**报告不会自动撤回任何校准码**，报告的数量也不构成撤回的依据——否则任何人都能用几个 Issue 让一份好的校准码下线。
是否撤回由维护者核实后决定，并在该 Issue 下说明结论。

## 撤销

维护者将 `index.json` 中对应条目的 `revoked` 改为 `true`，或执行：

```bash
python tools/publish.py revoke --repo . --code-sha256 <完整编号>
```

撤销不会删除条目。尚未启用该校准码的软件读到撤销标记后不再使用它；正在使用它、尚未完整核实的软件在重新读取索引时得知撤销，
停用它，并把它生成的记录标记为待复核。已完整核实、不再读取索引的共享档案，由软件在本机流量中判出矛盾后停用。
下载源存在缓存：`raw.githubusercontent.com` 数分钟内可见，jsDelivr 最多约 12 小时。jsDelivr 的缓存无法自助清除，因此 Action 不会尝试清除。

提交过被撤销校准码的账号，在该区服与客户端版本下暂停受理；Action 拒绝时会请提交者在 Issue 下说明情况。维护者复核后执行：

```bash
python tools/publish.py lift --repo . --account id:<数字编号> --region <CN 或 GLOBAL> --build <客户端版本>
```

该账号随即可以重新提交，被撤销的校准码本身仍不会再次发布。被撤销的校准码所占用的文件名（编号前 12 位）可以由另一份校准码重新使用。

## 清理旧版本

索引有大小上限，条目不会因提交而删除。维护者可以逐个写明要清理的客户端版本：

```bash
python tools/publish.py prune --repo . --region <CN 或 GLOBAL> --build <客户端版本> [--build <客户端版本> …]
```

不加 `--apply` 时只列出将被清理的版本、条目数、提交台账记录数与校准码文件，不改动任何文件；核对无误后加 `--apply` 执行。
被清理的版本连同其条目、提交台账记录与校准码文件一并移除，原文件仍保留在提交历史中。
脚本不按日期自行决定保留哪些版本，因为版本号由提交者给出，日期为当天的版本也会被受理。只应清理已无玩家使用的旧版本。

## 仓库布局

| 路径 | 内容 |
|---|---|
| `index.json` | 已发布校准码的索引，软件下载它（上限 64 KB、512 条） |
| `submissions.json` | 提交台账：哪个账号（数字编号）为哪个版本提交了哪份校准码，以及它替换掉的旧码；软件不下载该文件 |
| `cn/<客户端版本>/<编号前 12 位>.mrc` | 国服校准码文本，软件按添加它的提交号下载 |
| `global/<客户端版本>/<编号前 12 位>.mrc` | 国际服校准码文本 |
| `templates/<模板编号>.json` | 软件随包模板的逐字节副本，Action 用来按结构重建校验 |
| `tools/` | 校验与发布脚本，从 MentorRecorder 主仓库复制，不在本仓库内手工修改 |
| `.github/ISSUE_TEMPLATE/share-calibration.yml` | 提交表单 |
| `.github/ISSUE_TEMPLATE/report-calibration.yml` | 报告校准有误的表单 |
| `.github/workflows/publish-calibration.yml` | 自动校验、发布、回复；每 30 分钟补处理一次遗漏的提交 |
| `.github/workflows/report-calibration.yml` | 报告的校验、回复与打标签；不改动本仓库的任何文件 |
| `LICENSE.md`、`LICENSES/` | 许可 |

## 数据与隐私

- `submissions.json` 记录提交账号的 GitHub 数字编号，以及该账号此前被替换掉的校准码的校验值，仅用于执行受理规则中按账号计算的各项限制（每个账号每个版本同时只保留一份有效校准码、提交份数与每日次数上限、撤销后暂停受理）；该编号在对应的 Issue 上本就是公开的。
  该文件不会被软件下载，`index.json` 中不含任何账号信息。
- Action 只使用 GitHub 提供的默认 `GITHUB_TOKEN`，不需要任何其他密钥。
