# 副本提醒、导随宏与公共共享库

## 使用方式

- 主页的「副本提醒与导随宏」管理个人内容。打开「当前副本与通用」后按当前已识别的副本 ID 和区服筛选。BOSS、阶段、角色和游戏版本是内容字段。阶段通过界面筛选，游戏版本供玩家判断适用性。
- 提醒可以关联多条宏。关联的条目可在预览中打开，单条或批量提交和导出会带上关联项。选择「收藏」和「显示顺序」可整理本地条目。个人导随心得仍随某条历史记录保存。
- 复制按钮会先展示正文。提醒按普通文本复制，队聊／团聊只允许一条带正文的 `/p` 或 `/a`，完整宏可保留多行及 `<t>`、`<me>`、`<wait.1>` 等占位符。完整宏最多 15 行。另设保守的应用端限额，每行宏最多 180 UTF-8 字节，一条聊天指令最多 500 UTF-8 字节，包含命令本身。这两个字节上限需在目标区服客户端实测确认。超限会显示错误。
- 主界面和浮窗在已匹配且副本可可靠识别时即可打开副本攻略，进本后继续跟随最新识别结果。完整浮窗和迷你条的书本按钮在解锁时常驻，空闲、未识别或站点未收录时打开攻略目录。历史详情按当前选中的记录解析链接。
- [攻略对照表](../data/duty-guides/ff14-org.json) 收录 267 个实际网页链接。上游为《新大陆见闻录》的公开目录部署文件，对照游戏目录的编号、名称、等级、人数和区域。6 个防剧透标题按相同编号、难度后缀、类别、等级和人数核对。运行时按区服与副本标识查找，四个区域编号与国服不同的繁中服副本有独立对照。只有区域编号时须确认该区服的区域仅对应一个副本。
- 公共库独立联网开关默认关闭。开启后点「刷新公共库」才会检查远端，有效缓存和本地内容可以离线使用。选择条目可预览全文、来源、作者、区服、语言、许可和核验状态，导入时连同可用的关联项一起保存。来源更新可前后对比后应用，默认推荐保留本地改过的字段。采用来源版本需要主动操作。另存个人版本会生成新的本地 ID，并保留来源。来源标记过时或撤回时显示状态，个人记录留存。

## 投稿

1. 选中条目，检查公开预览并明确选择 CC BY 4.0 或 CC BY-SA 4.0。只发布你有权授权的内容。附带来源的个人版本应保留原作者和许可信息。
2. 「原生提交」使用 GitHub 官方设备授权和用户自己的身份提交到 `Harendotes-Tang/MentorRecorder-Calibrations`。作者以 GitHub 账号 ID 为准。浏览器备用入口会复制完整块、打开 Issue 表单，需手动粘贴并提交。
3. 原生提交返回 Issue 编号。也可将浏览器投稿的编号填入软件，主动查询已提交、处理中、已公开发布、关闭或处理失败。工作流回执提供发布 ID。作者需要更新原 ID 时，先手动刷新公共库，以便在新 Issue 投稿中携带基准修订号。改编者使用另存后的 ID。
4. 格式和校验值只说明传输完整性及格式一致性。首发和作者改稿均为社区投稿／未核验。维护者可手动运行社区发布工作流，填稳定 ID、当前修订号与核验／过时／撤回状态。

## 公共仓库维护与部署

主项目的 `tools/shared-calibration/` 托管发布工具和工作流源。在已有公共仓库的干净 checkout 运行：

```powershell
python tools/shared-calibration/sync_public_repo.py --out <public-checkout> --update-existing
```

该模式同步明确管理的文件，社区初始索引与台账只在两者均不存在时写入。先审核变更，再通过公共仓库的正常合并流程发布。校准索引、证据、投稿记录和校准码应留在原处。只有在隔离的 Actions checkout 或测试临时仓库中运行自动发布脚本。

- 公共仓库需要启用 Issues 和 Actions。允许工作流写入 Issues 与仓库内容，确认 main 的保护规则兼容 Actions 快进写入。创建标签 `community-content`、`community-published`、`community-failed`、`community-classification`。
- 工作流通过结构化正文接收无标签 Issue，使用实时 Issue 和 GitHub 作者记录，重复事件、修订与遗漏交由持久化台账和定时补扫处理。所有写 main 的公共工作流共享 `publish-calibration` 并发组。每隔半小时补扫。镜像继续使用现有的 `GITCODE_MIRROR_TOKEN`，监听各发布工作流完成及定时同步。分支/CDN 缓存和 GitCode 镜像会造成延迟，客户端拒绝覆盖已安装的较新快照。
- 在仓库所有者的 GitHub 账号下创建 GitHub App，启用 **Device Flow**，仅授予仓库 **Issues: Read and write**，安装时仅选 `MentorRecorder-Calibrations`，允许普通 GitHub 用户授权。将公开的 **Client ID** 配置为启动 Collector 的 `MENTORRECORDER_COMMUNITY_CLIENT_ID` 环境变量并重启软件。通过应用授权页验证普通用户授权后拥有在公开库发 Issue 的能力，再用非协作者账号验收。令牌刷新使用设备授权取得的 refresh token 与公开 Client ID。
- 原生授权取消后停止轮询，过期后重新发起。退出软件内 GitHub 登录会清除本机凭据。如需彻底撤销 GitHub 端的授权，在 GitHub 设置的 Authorized GitHub Apps 中撤销。
- 联调需使用普通投稿者与未登录导入者两个实例。测试投稿应使用自写通用内容，并经仓库维护者允许在公开仓库留下测试记录。

格式定义见 [社区 JSON Schema](../contracts/community-content-v1.schema.json) 和 [IPC 契约](../contracts/ipc-v1.schema.json)。来源站点的攻略正文始终由浏览器访问。
