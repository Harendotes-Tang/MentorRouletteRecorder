# 副本提醒、导随宏与公共共享库

## 使用方式

- 总览「当前导随」标题行右端有两个入口：「攻略目录 ↗」（已识别的副本有对应页面时为「查看攻略 ↗」）和「提醒与宏」。进本后「提醒与宏」带上本地属于当前副本的条数。
- 「提醒与宏」打开的弹窗管理个人内容：标题旁切换「本地」与「公共共享库」，下方一行搜索与四个筛选（类型、职业、区服、语言，均可多选并显示条数，两个标签各自保存），再下面分三栏：左边「副本目录」、中间列表、右边所选条目。投稿在右栏完成；新建和编辑时表单占满弹窗，标签、筛选、列表和投稿进度暂时收起，「保存」、Ctrl + S 保存，「取消」、Esc 或左上角「← 副本提醒与导随宏」回到列表（不保存）。进本时打开，目录停在「当前副本」（按当前已识别的副本 ID 和区服），不在副本里时停在「全部」。表单左边是类型、标题和正文，只有标题和正文必填；宏的正文带行号，一屏可看 15 行，超过 15 行的行号和计数变红，提示拆成两个宏但不阻止保存，「插入」可加入小队频道 `/p`、只给自己看 `/e`、提示音 `<se.1>`、等几秒 `<wait.3>` 和当前目标 `<t>`，指令另起一行，占位符插在光标处；提醒不显示行号，自动换行。右边一列「适用范围」都可以不填，不填就是都适用：副本（「通用」即不限；进本时默认当前副本；按类型分组，可按名称或编号搜索）、BOSS / 阶段（从已有内容给出建议）、职业（仅宏）、游戏版本、区服（默认取页头所选的记录区服，所选为「全部区服」或未知区服时为全部区服，可另行指定）和语言。职业按职能分组多选，可按名称或缩写搜索；整个职能选中时保存职能本身（`TANK`、`HEALER`、`MELEE`、`RANGED`、`CASTER`），以后新增的职业也算在内，单独勾选的职业保存职业缩写，都写入内容的 `role` 字段（如 `TANK,BRD`），各语言客户端通用。游戏版本从两个下拉框选择开始和结束版本（各资料片的 x.0 至 x.5，「不限」表示不限制），开始晚于结束时立即提示；保存在内容的 `game_version` 文本字段中，只选结束版本写作 `-6.0`（显示为「到 6.0」），两端都选写作 `6.0-7.3`，只选开始版本写作 `7.3-`（显示为「7.3 → 最新」）。`role` 和 `game_version` 中手写的其他文字显示在对应字段下方，未清除时原样保留。BOSS 和阶段在表单中合为一栏，内容改动后保存为 BOSS；标签和来源不在表单中，导入或公共库带来的值在保存时原样保留。BOSS / 阶段可在界面中筛选，游戏版本供玩家判断适用性。没有内容时可从常用宏示例开始：实盾姿、单点攻击、无敌提醒宏、OT宏、禁止攻击宏和辛苦宏，正文按国服客户端写成，不随界面语言翻译。
- 「副本目录」决定列表显示哪些内容：上面是固定范围「全部」「当前副本」「收藏」「最近用过」（后两项只在本地）和「通用」，下面按副本类型列出有内容的副本，类型内按等级排，没有内容的副本不列。每一项后面的数量随搜索和筛选变化，搜一个词就能看出命中都在哪些副本里。点类型名称查看这一类的全部内容，点箭头展开或收起；「找副本」按名称或编号查找。「最近用过」是最近复制过的 30 条本地内容，只记在本机。
- 列表在「当前副本」和某个副本里按 BOSS / 阶段分组：开场、全程、道中、BOSS 1 至 9、尾王、阶段 1 至 9、转场、结束，没有填的归入「未标阶段」，「当前副本」里通用的内容排在最后（本地内容较多时先显示 5 条）。BOSS / 阶段是手写的，分组前先归一，例如「BOSS 2」「2 号 BOSS」「老二」「Boss 2」「2ボス」是同一组；认不出的写法按原文单独成组。在某一类副本里按副本分组，每个副本先显示 8 条，「查看全部」进入该副本；其余范围不分组。组标题滚动时停在列表顶部，点一下收起或展开，表头的「全部收起」作用于所有组。表头另有排序（本地：最近更新、最近用过、按标题；公共库：最近更新、已核验的在前、按标题）和「紧凑」行高，这两项与公共库的区服、语言选择会被记住；每次打开时搜索、类型和职业筛选清空，目录回到「当前副本」或「全部」。「全选」勾选整个范围，包括收起的组。搜索只在目录选中的范围内进行，命中的文字加粗显示，命中在正文时第二行显示命中的那一句；别的范围也有命中时，列表末尾给出「去看看」。Ctrl + F 跳到搜索框。保存、导入后查看某一条时，目录切到它所在的副本并展开它所在的组。
- 提醒可以关联多条宏：在提醒的右栏选择「从提醒生成宏」，新建的宏自动关联这条提醒；导入内容自带的关联保持不变。关联的条目可在预览中打开，单条或批量提交和导出会带上关联项。勾选条目后，列表底部显示已选条数和批量操作，右栏的「导出」「投稿」也改为处理勾选的条目，按钮上写明条数；没有勾选时只处理正在查看的这一条。列表和右栏中的星标用于收藏本地条目。个人导随心得仍随某条历史记录保存。
- 右栏显示正文，宏带行号与「n / 15 行」计数。「复制」把提醒按普通文本、宏按完整多行复制（保留 `<t>`、`<me>`、`<wait.1>` 等占位符）；只有一行的宏另有「复制队聊／团聊消息」，只允许一条带正文的 `/p` 或 `/a`。完整宏最多 15 行。另设保守的应用端限额，每行宏最多 180 UTF-8 字节，一条聊天指令最多 500 UTF-8 字节，包含命令本身。这两个字节上限需在目标区服客户端实测确认。超限会显示错误。
- 主界面和浮窗在已匹配且副本可可靠识别时即可打开副本攻略，进本后继续跟随最新识别结果。完整浮窗和迷你条的书本按钮在解锁时常驻，空闲、未识别或站点未收录时打开攻略目录。历史详情按当前选中的记录解析链接。
- [攻略对照表](../data/duty-guides/ff14-org.json) 收录 267 个实际网页链接。上游为《新大陆见闻录》的公开目录部署文件，对照游戏目录的编号、名称、等级、人数和区域。6 个防剧透标题按相同编号、难度后缀、类别、等级和人数核对。界面语言为简体中文或繁體中文时打开《新大陆见闻录》；为英语或日语时打开 Console Games Wiki（`https://ffxiv.consolegameswiki.com/wiki/<英文副本名>`，日语暂用英文站），页面标题取随包的英文副本名，对照表中 267 个副本有 265 个与该站标题一致（2026-11-24 核对），其余 2 个在代码中单独列出；没有对应页面时打开该站的 Duties 页面。哪些副本有对应页面不随语言变化。运行时按区服与副本标识查找，四个区域编号与国服不同的繁中服副本有独立对照。只有区域编号时须确认该区服的区域仅对应一个副本。
- 公共库独立联网开关默认关闭，联网状态、「刷新」和开关在「副本目录」下方。开启后，每次切换到「公共共享库」或点「刷新公共库」时检查远端（距上次检查不到 30 秒、或上次成功后不到 2 分钟时沿用上次结果；尚无缓存时的「允许联网并刷新」一次完成开启和刷新），刷新先读 GitHub，3 秒内没有读完时同时改读 GitCode 镜像，采用先读到的一方；有效缓存和本地内容可以离线使用。公共库打开时先只显示所选记录区服和界面语言的内容（该区服没有这种语言的内容时只按区服），列表末尾写明另有多少条属于其他区服或语言，点「也显示出来」或在「区服」「语言」筛选里取消勾选查看其他内容；改过区服或语言筛选后，以后沿用所改的选择。「清除筛选」只清除搜索、类型和职业，不改动公共库的区服和语言。选择条目可预览全文、来源、作者、区服、语言、许可和核验状态（没有填写的职业、游戏版本不显示，许可只写代号，悬停时说明含义，更新时间按本机时区显示为日期），导入时连同可用的关联项一起保存。来源更新可前后对比后应用，默认推荐保留本地改过的字段。采用来源版本需要主动操作。另存个人版本会生成新的本地 ID，并保留来源。来源标记过时或撤回时显示状态，个人记录留存。
- 「职业」筛选在本地和公共库都可使用。选职能时也包括只标了其中某个职业的内容，选职业时也包括标了它所属职能的内容，「不限职业」是没有标职业的内容；`role` 是手写文字的条目在选了任何职业时都不显示。正文读起来几乎一样的同类型条目（只差提示音、空格、全角半角等兼容字符、大小写或个别字）折叠在一组里，列表只显示其中一条：已核验的优先，否则取 Issue 编号最小的一条，它被筛选掉时取列表中排在最前的一条。这一条下面写「另有 N 条相似」，点开后其余条目缩进列在它下面。打开、勾选和「全选」只作用于列表上显示的条目；从关联项打开收起的条目时，所在的组自动展开。

## 投稿

1. 选中条目，检查公开预览并选择许可：「注明作者即可转载、改编」（CC BY 4.0）或「注明作者，改编后也须同样共享」（CC BY-SA 4.0），下拉框下方用一句话说明别人可以怎样使用；条目详情中的许可也这样显示。只发布你有权授权的内容。附带来源的个人版本应保留原作者和许可信息。
   公共库里已有的内容不会再投：与已刷新公共库中某条同类型内容正文相同的，或者就是公共库里那一条且没有改动的，在预览中标明原因，不计入投稿条数（一次最多投稿 20 项，按实际投稿的条目计），指向这类新条目的关联改为指向公共库那一条。自己已发布的条目只改标题等其他字段、正文不变时照常投稿，即使公共库里另有正文相同的较早条目。公共库没有刷新过时，由工作流判断。
2. 「原生提交」使用 GitHub 官方设备授权和用户自己的身份提交到 `Harendotes-Tang/MentorRecorder-Calibrations`。作者以 GitHub 账号 ID 为准。浏览器备用入口会复制完整块、打开 Issue 表单，需手动粘贴并提交。
3. 原生提交返回 Issue 编号。也可将浏览器投稿的编号填入弹窗底栏的「投稿进度」，主动查询已提交、处理中、已公开发布、关闭或处理失败。工作流回执提供发布 ID。作者需要更新原 ID 时，先手动刷新公共库，以便在新 Issue 投稿中携带基准修订号。改编者使用另存后的 ID。
4. 格式和校验值只说明传输完整性及格式一致性。首发和作者改稿均为社区投稿／未核验。维护者可手动运行社区发布工作流，填稳定 ID、当前修订号与核验／过时／撤回状态。
5. 相同正文只发布一次。「正文相同」指同类型、统一换行并去掉行尾空白和首尾空行后完全一致，撤回的条目不算。工作流先判断作者对已发布条目的修改：按条目 ID 的顺序、对照投稿改动后的公共库反复比较，直到没有变化，因此这些修改在投稿中的先后不影响结果；再按投稿中的顺序判断新条目：新条目与已有条目或同一份投稿中前面的新条目正文相同时跳过，其他条目对它的关联改为指向已发布的那条；修改后的正文与其他已发布条目相同时保留原来已发布的版本，指向它的关联不变；只改标题等其他字段、正文不变的修改照常发布。其余条目照常发布，回执列出被跳过条目的 ID 和与之相同的已发布条目 ID 及作者。既没有新发布的条目、也没有保持不变的条目时，加 `community-duplicate` 标签，「投稿进度」显示「没有重复发布」；作者原样重投自己已发布的条目算作保持不变，显示「已公开发布」。读起来几乎一样的（NFKC 规范化、去掉提示音 `<se.N>` 和空白、转小写后，相邻字符对的 Dice 系数不低于 0.9）照常发布，回执列出相似条目的 ID 和作者，并在第一次回执时加 `community-similar` 标签供维护者查看；维护者看过后可以移除这个标签，同一份投稿不会再加上它，必要时把其中一条标为过时或撤回。软件与工作流使用同一套比较规则（`src/Desktop/qml/dialogs/DutyCommunityMatch.js`、`tools/shared-calibration/community_publish.py`），两边的测试都运行 `tests/Fixtures/shared-calibration/community-text-vectors.json` 中的同一组用例。

## 公共仓库维护与部署

主项目的 `tools/shared-calibration/` 托管发布工具和工作流源。在已有公共仓库的干净 checkout 运行：

```powershell
python tools/shared-calibration/sync_public_repo.py --out <public-checkout> --update-existing
```

该模式同步明确管理的文件，社区初始索引与台账只在两者均不存在时写入。先审核变更，再通过公共仓库的正常合并流程发布。校准索引、证据、投稿记录和校准码应留在原处。只有在隔离的 Actions checkout 或测试临时仓库中运行自动发布脚本。

- 公共仓库需要启用 Issues 和 Actions。允许工作流写入 Issues 与仓库内容，确认 main 的保护规则兼容 Actions 快进写入。创建标签 `community-content`、`community-published`、`community-failed`、`community-classification`、`community-duplicate`、`community-similar`。
- 工作流通过结构化正文接收无标签 Issue，使用实时 Issue 和 GitHub 作者记录，重复事件、修订与遗漏交由持久化台账和定时补扫处理。社区发布使用自己的 `publish-community` 并发组，与校准发布、证据和报告各自排队，推送被拒时从最新的 main 重做。每隔半小时补扫。镜像继续使用现有的 `GITCODE_MIRROR_TOKEN`，监听各发布工作流完成及定时同步。分支/CDN 缓存和 GitCode 镜像会造成延迟，客户端拒绝覆盖已安装的较新快照。
- 在仓库所有者的 GitHub 账号下创建 GitHub App，启用 **Device Flow**，仅授予仓库 **Issues: Read and write**，安装时仅选 `MentorRecorder-Calibrations`，允许普通 GitHub 用户授权。将公开的 **Client ID** 配置为启动 Collector 的 `MENTORRECORDER_COMMUNITY_CLIENT_ID` 环境变量并重启软件。通过应用授权页验证普通用户授权后拥有在公开库发 Issue 的能力，再用非协作者账号验收。令牌刷新使用设备授权取得的 refresh token 与公开 Client ID。
- 原生授权取消后停止轮询，过期后重新发起。退出软件内 GitHub 登录会清除本机凭据。如需彻底撤销 GitHub 端的授权，在 GitHub 设置的 Authorized GitHub Apps 中撤销。
- 联调需使用普通投稿者与未登录导入者两个实例。测试投稿应使用自写通用内容，并经仓库维护者允许在公开仓库留下测试记录。

格式定义见 [社区 JSON Schema](../contracts/community-content-v1.schema.json) 和 [IPC 契约](../contracts/ipc-v1.schema.json)。来源站点的攻略正文始终由浏览器访问。
