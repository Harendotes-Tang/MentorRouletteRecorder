# 繁中服測試與採證步驟

這次想請你協助確認：繁中服客戶端能否被辨識、遊戲資料能否正常解碼，以及排隊到離開副本各階段出現了哪些訊號。請先做一輪，將檔案回傳；確認資料可用後，再補第二輪。

請從 GitHub 發布頁下載 **1.9.0-beta.1** 測試版（標為 Pre-release）：<https://github.com/Harendotes-Tang/MentorRouletteRecorder/releases/tag/v1.9.0-beta.1>，執行 `MentorRecorder-1.9.0-beta.1-setup.exe` 安裝；發布頁上若已有更新的測試版，用最新的一版即可。發布頁同時提供 `.sha256` 校驗檔，可用 PowerShell 的 `Get-FileHash -Algorithm SHA256` 核對下載的檔案。軟體內的檢查更新只提供正式版，測試版需自行下載。目前繁中服自動記錄仍顯示「不支援」；採證期間不會自動新增正式導隨紀錄，這是本輪預期。

## 一、開始前

1. 若原本已有正式記錄，請先用原版本的「設定 → 資料 → 立即備份」保存備份，留在自己電腦，不用回傳。測試版會升級記錄資料庫；舊版不能直接讀取升級後的資料庫，需要退回時再聯繫我按備份恢復。
2. 記下軟體版本、Windows 版本、繁中服遊戲版本，以及是否使用加速器／VPN。遊戲版本請以遊戲客戶端版本為準，不要填啟動器版本。
3. 確認 Npcap 可用；安裝時需啟用 **WinPcap API-compatible Mode**。若軟體提示未安裝、相容模式缺失或權限不足，先回傳提示截圖，處理好再採證。
4. 先完全退出遊戲，開啟測試版。在設定中將「遊戲區服」明確選成 **「繁中服 TC」**，不要選「自動」或「國際服 GLOBAL」。區服不能修改時，確認遊戲已退出，並等待監聽／採證停止。這項選擇會綁定到選擇之後第一個執行的遊戲客戶端，也就是本輪的繁中服客戶端。測試結束、要回到國服遊玩前，請將「遊戲區服」改回「自動（安裝路徑）」：安裝路徑表明為國服的客戶端不會被改標為繁中服，但改回之前會暫停自動記錄並顯示提示。
5. 本輪請維持原本的網路與加速器設定。若中途更換設定或斷線，記在回報中，不要把前後不同條件當成同一輪正常採證。

## 二、先做介面檢查（無需排本）

- 切換繁體中文或其他介面語言，確認「遊戲區服」仍保留 TC；介面語言與遊戲區服是分開的。
- 在總覽的「全部區服」視圖，確認國服與繁中服的成就進度分開顯示，沒有加成一個總數。若原本已有國服資料，確認原本的數字仍在。
- 若願意測試成就設定：先記下繁中服原本的「目標值」與「起始次數」，選繁中服修改一次，原因填「繁中服測試」。確認國服沒有跟著變，再恢復繁中服原值；等保存完成後重開軟體，檢查是否保留。若不方便動原資料，這項可跳過並註明。
- 打開手動補錄，將該筆記錄的區服選成繁中服，看看副本清單與名稱是否正常；只檢查清單即可，不必保存。若名稱與遊戲不同，記下軟體名稱及遊戲名稱。
- 若已有測試用記錄，可順便檢查歷史／統計的「全部區服、國服、繁中服」篩選。沒有記錄時寫「空資料，未測」，不用為此提供自己的整份歷史資料。

有異常時，保留畫面截圖及重現操作即可。

## 三、開始採證

1. 進入 **「擷取診斷」→「工具」→「協助支援其他伺服器地區」→「採證步驟」**，打開「新區服採證」頁面；一輪進行中或剛結束時，該按鈕顯示為「繼續」。簡體介面對應「捕获诊断 → 工具 → 帮助适配其他区服 → 采证步骤」。頁面依序列出五個步驟，下文的 ①～⑤ 即指這五步。
2. 第 ① 步「選擇區服和網卡」：再確認區服是「繁中服 TC」。網路介面卡先用「自動選擇（唯一推薦網卡）」；若無法選出唯一推薦介面，再按畫面提示選目前遊戲使用的網卡。先前選過的網卡已不可用時，頁面會提示改選，改選之前不能開始。
3. **遊戲必須先完全結束。** 遊戲正在執行時「開始採證」不能按，頁面顯示「遊戲正在執行：先完全結束遊戲，再開始採證」；結束遊戲後按「已經結束了，重新偵測」。頁面顯示「遊戲未執行，可以開始」後按 **「開始採證」**，然後啟動遊戲，先停在標題畫面。
4. 第 ② 步：等頁面顯示 **「正在取證 · 可以登入了」**，再登入角色。若顯示等待遊戲、選擇客戶端或網卡等提示，先照提示處理；等待時不能打標記，也可以按「取消等待」放棄本輪。
5. **若提示已有連線、需要重啟遊戲：保持採證等待，完全關閉遊戲客戶端後重新啟動。** 只登出回標題或傳送換區，不能代替這次重啟。仍無法進入「正在取證」時，截圖回傳即可，不必反覆嘗試。
6. 登入後正常走動約 30～60 秒，查看「報文」是否持續增加；頁面顯示「資料可讀，接著排本」即可進入第 ③ 步。頁面顯示「資料異常」（「報文一直為 0」，或解碼失敗快速增加）時，先截圖，再按「停止並匯出診斷」；不用接著排完整副本。「報文一直為 0」只在遊戲已經連上伺服器 60 秒後仍沒有報文時才會出現，停在標題畫面等待不會觸發。第 ② 步也隨時可以按「停止採證」結束本輪。正式記錄區的解析／記錄數為 0，不能單獨用來判斷採證失敗。「報文」為 0 或解碼失敗持續增加，多半表示軟體還不會解開繁中客戶端的網路壓縮；這種情況下第二輪會另外提供一個只讀取遊戲主程式檔案副本的簽名工具與步驟，本輪不用自行處理。

## 四、完整走一次排隊到離本

能排 **「隨機任務：指導者」** 的話，優先採這一種。沒有資格時，請直接註明；也可採一次能排的一般隨機任務作對照，但不能把它當成指導者隨機證據。請記下隨機任務種類、實際進入的副本名稱及職業。

先在採證頁面第 ③ 步「排一把隨機，按事件標記」選好隨機類型（指導者隨機或其他隨機）。在遊戲事件發生當下，切到這一步點對應按鈕，最好在約 3 秒內完成：

1. 按下遊戲的開始排隊後 → 點 **「已排隊」**。
2. 遊戲跳出配對成功／進入確認視窗時 → 點 **「已配對」**。
3. 讀取完成、進入副本時 → 點 **「已進入」**。
4. 出現副本通關提示時 → 點 **「已勝利」**。
5. 離開副本、回到外面時 → 點 **「已離開」**。

漏按、重複點、延遲較久、取消排隊、拒絕配對、途中加入、斷線或未通關，都請如實寫在回報；其中中途加入、未通關、漏按、點晚與斷線，也可以在「這一輪的情況」中勾選，會一併寫進回傳說明。不要在結束後補點成一套完整流程；未通關就不點「已勝利」。

單次採證最長 2 小時，包含等待與重啟時間。建議每輪任務各存一份；若第一輪資料可用、時間也方便，再用相同方式採第二輪。不同副本／職業請照實分別記錄。

## 五、停止與保存

1. 離本並打完最後標記後，按 **「停止採證」**，等待狀態變成 **「已儲存」**。不要在「正在儲存」時直接退出軟體。
2. 截下採證頁面，包含保存狀態，以及「報文」「已寫入標記」「解碼失敗」「佇列丟棄」四項計數。若顯示「採證失敗」或「已結束，檔案不完整」，保留當下畫面並註明，不當成正常完成；這時第 ④ 步仍會列出已有的檔案，照樣回傳，缺的檔案會寫進回傳說明。
3. 在第 ④ 步的檔案清單中，按 `trace.jsonl` 一行的 **「開啟所在資料夾」**，將本輪的整個採證資料夾複製到桌面。裡面應有 `trace.jsonl` 及 `trace.jsonl.sha256`。保留原檔名、原內容，兩個檔案一起保存；不要手動修改 JSONL 或重新產生校驗檔。
4. 按「診斷報告 JSON」一行的 **「匯出診斷報告」**，選擇保存位置。建議存到同一份回傳資料夾；軟體建議的名稱是 `mentor_diagnostics_日期時間.json`，保留實際產生的名稱即可。需要附日誌時，按 `collector-*.log` 一行的「開啟日誌資料夾」。
5. 按 **「下一步：產生回傳說明」** 進入第 ⑤ 步，填寫副本、職業與加速器／VPN，確認「這一輪的情況」，再按 **「複製回傳說明」**。回傳說明已自動填入版本、時間、區服、標記與計數，貼到 `測試回報.txt` 開頭，再依下方格式補齊其餘項目。
6. 在按「開始下一輪」、重開軟體或換網路前，先完成本輪資料複製。軟體內的採證目錄只保留最近 10 份，且不超過 7 天；複製到桌面的那份請自行保留到確認收到。

**候選摘要可另外附上，取不到也不必卡住：**

- 「已儲存」後，可在第 ⑤ 步展開「候選摘要（可選）」，按「預覽候選摘要」。它只反映候選線索，不能證明自動記錄已可用。
- 若願意使用「複製摘要並開啟送出頁面」，它會複製完整 JSON 並開啟 GitHub 表單，頁面可能預填摘要。這輪不用送出 Issue；將剪貼簿內容貼到記事本，以 UTF-8、所有檔案類型另存為 `tc_observation_01.json`，回傳給我即可。不要截斷或修改內容。
- 不想開啟 GitHub，或預覽失敗時，這項可以略過。先記下提示，回傳採證檔與診斷即可。摘要只對目前最近的一次採證提供，請在下一輪或重開軟體前處理。

## 六、需要回傳哪些檔案

請將下列資料放進同一個資料夾，壓縮成 ZIP，寄到 **mentorrecorder@gmail.com**，主旨寫成
「[TC 採證] 日期 第 N 輪」，例如「[TC 採證] 2026-11-05 第 1 輪」。附件上限 25 MB，超過時分成兩封寄，
或改附 Google 雲端硬碟連結；請勿貼到公開 Issue 或聊天群。回傳內容：

- **每次都需要：`測試回報.txt`**，依下方格式填寫；未測、失敗或沒有資格都可直接寫明。
- **能匯出時需要：`mentor_diagnostics_*.json`**，即軟體內匯出的診斷報告。若匯出本身失敗，提供錯誤截圖代替並註明。
- **有產生採證檔時需要：每輪的 `trace.jsonl` 與 `trace.jsonl.sha256`。** 兩輪請各放在不同子資料夾，避免同名覆蓋；失敗輪次產生的檔案也保留，標明失敗原因。失敗時可能只有 JSONL、沒有校驗檔，回傳現有檔案並註明即可；完全沒有產生檔案就寫「未產生」，不必自行建立空檔。
- **截圖：採證最終狀態；有異常時再附異常畫面。** 若方便，可補配對確認、遊戲內副本名稱或通關提示的截圖，並標明對應輪次。遮掉不想分享的角色名、聊天及其他個人資訊。
- **可取得再附：`tc_observation_01.json` 等候選摘要。**
- **想列入致謝時：** 在信中寫上希望列出的名稱（例如「角色名@伺服器」或暱稱），會列在 README 的致謝中；不寫就不列。
- **啟動／採證異常時再附：對應時間的 `collector-*.log` 診斷日誌。** 可在第 ④ 步按「開啟日誌資料夾」，或從「設定 → 資料 → 開啟資料夾」進入資料庫所在目錄，再查看 `logs` 子資料夾；只複製本輪時間對應的日誌，不要把資料庫一起打包。若找不到，先回傳其他資料並註明。
- **遊戲版本識別不出時再附：客戶端 `game` 目錄內的 `ffxivgame.ver` 小文字檔。** 只需這個檔案，不用整個遊戲目錄。

不需要遊戲 EXE／DLL、整份記錄資料庫、帳號密碼或 Wireshark 原始封包。內建採證檔不保存報文正文，但保留時間與本輪關聯資訊；完整 `trace.jsonl` 只私下回傳，不貼到公開 Issue。診斷報告不能取代採證檔，截圖也不能取代原始 JSONL 與校驗檔。

## 測試回報格式

```text
軟體版本／測試包名稱：
Windows 版本：
遊戲客戶端版本：
測試日期、開始與結束時間（含時區，例如 UTC+8）：
是否可排「隨機任務：指導者」：
網路：有線／Wi-Fi；加速器或 VPN 名稱、是否全程相同設定：

介面檢查結果：
TC 區服保存／切換語言：正常／異常／未測
兩區成就分開顯示、設定互不影響：正常／異常／未測
繁中副本名稱、記錄區服篩選：正常／異常／未測

第 1 輪：
對應的採證子資料夾：
隨機任務種類／實際副本名稱／職業：
一般開局進入或途中加入：
有無配對彈窗、是否通關、是否正常離本：
有無漏按／延遲／重複標記、取消配對、斷線或更換網路：
採證最終狀態及四項計數（也可見截圖）：
候選摘要：已附／未取得；若未取得，畫面提示：
異常或希望補充的內容：

第 2 輪：可複製上段填寫；未採第二輪請寫「未測」。
```

本輪先確認資料是否能讀取並定位候選訊號。若還需要確認報文裡的欄位，會再提供限定範圍的補採步驟；完成這份採證本身，不代表繁中服自動記錄已驗證通過。
